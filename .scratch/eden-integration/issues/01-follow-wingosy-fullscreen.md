# 01 — Follow Wingosy Fullscreen

**What to build:** Update Eden launch handling so its display mode follows the live Wingosy launch context from both existing launch entry points. Eden should receive fullscreen intent only when Wingosy is currently fullscreen or immersive; a normal windowed launch must leave Eden’s own display preference alone. Keep the existing Wingosy hide/restore lifecycle and leave every non-Eden emulator path unchanged.

**Blocked by:** None — can start immediately
**Status:** resolved

## Acceptance criteria

- [x] Both existing Eden launch entry points evaluate the current Wingosy display context at launch time.
- [x] A currently fullscreen Wingosy launch starts Eden fullscreen.
- [x] An immersive Wingosy launch starts Eden fullscreen, even when desktop fullscreen is not separately selected.
- [x] A normal windowed launch does not force Eden fullscreen or overwrite Eden’s saved display preference.
- [x] The change does not introduce a second persistent Eden fullscreen preference or a force-windowed promise.
- [x] Existing Wingosy hide/restore behavior remains intact for Eden launches.
- [x] Launch behavior for other emulators remains unchanged.

## Verification

- [x] Automated behavioral coverage exercises the shared pipeline used by both entry points through fullscreen, immersive, and normal windowed contexts.
- [ ] Human check: launch Eden once from immersive mode and once from a normal windowed state; confirm the two display outcomes.

## Scope boundaries

- Display handling only; no broad display-settings redesign, installer work, or emulator update management.
- Do not change other emulator launch paths to share or consume Eden-specific behavior.
